# Architecture

This document walks the system end to end. The research report remains the
design source of truth; here we describe the implementation as built.

## 1. System overview

```
                      +-----------------------------------------------+
                      |              PHASE 1 - PrismaForge            |
                      |                                               |
  GitHub repos -----> | 01 crawl -> 02 extract -> 03 clean ----------+ |
  (mined track)       |                                 |            | |
                      |                                 v            v |
  12 domain           | 04 synthetic -----------------> 06 verify     |  verified/
  archetypes -------> | 05 augment                        gates V1-V5 |  pools
                      |                                             | |
                      +---------------------------------------------|-+
                                                                    v
                      +-----------------------------------------------+
                      |  07 split (database-level + firewall)         |
                      |  08 finalize (train/val/test/benchmark.jsonl) |
                      +-----------------------------------------------+
                                        |
        +-------------------------------+--------------------------+
        v                               v                          v
  PHASE 2 PrismaBench           PHASE 3 Training            SFT/DPO pairs
  generator -> public/        S0 CPT -> S1 SFT -> S2 DPO
  private/ -> evaluator           (QLoRA default)
        |                               |
        v                               v
  leaderboard + error      PHASE 4/5 Evaluation + Inference
  taxonomy (E1-E10)        repair loop -> FastAPI / Gradio / HF Space
```

## 2. Canonical record contract

Every artifact in the system - mined, synthetic, augmented, benchmark - is a
JSON record validated by `prismacoder/schema.py` and `datasets/schema.json`
(JSON Schema draft 2020-12). Key fields: `source` (track, license,
provenance hash), `domain` (12 archetypes), `task` (type T1-T12, instruction,
context.schema, reference, persona, tests), `verification` (status + gates),
`difficulty_scores` (models/relations/nesting/ops/ambiguity), `style_tags`,
`meta` (seeds, tags, canary). Records may carry `preference` (DPO pair) and
`reasoning` (plan-span) blocks.

## 3. The PSL spine

`prismacoder/psl.py` is the shared spine: a dependency-free parser/renderer
used by cleaning (schema sanity), dedup (model-graph isomorphism signatures),
the synthetic sampler (rendering), the LightValidator (symbol grounding), the
hallucination metric, and tree-edit-distance. Model objects expose
`relation_fields()`, `scalar_fields()`, `primary_key()` so reference composers
emit client code grounded in the actual schema.

## 4. The verifier stack

```
                    SandboxProject (package.json pinned: prisma, ts, vitest, tsx)
                       |
   V1 validate  <-- npx prisma validate / format
   V2 generate  <-- npx prisma generate         (codegen gate)
   V3 tsc       <-- npx tsc --noEmit            (type gate)
   V4 execute   <-- prisma db push (+optional postgres lane, migration dry-run)
   V5 vitest    <-- npm test (JSON reporter)
                       |
   short-circuit on first failure -> diagnostics -> classify_error -> E1-E10
```

Run modes: host (Node >= 18.18), docker verifier service
(`docker/verifier/worker.py`, `POST /verify`), or LightValidator static mode
(fence balance + schema parse + symbol grounding; records marked
`unverified`). Gate outcomes feed:

1. **Data filter** - stage 06 sweep; failed records become DPO negatives.
2. **Reward** - GRPO weights `0.25*V1 + 0.15*V2 + 0.20*V3 + 0.40*V5` (+style,
   -hack) from the report.
3. **Repair loop** - `PrismaCoderPipeline.run()` feeds gate diagnostics back
   into the model context until green or the attempt budget expires.

## 5. Synthetic generation discipline

"Teachers write questions, mechanics write answers": instructions come from
the persona verbalizer (deterministic templates; optional LLM teacher hook),
while every reference is composed from the sampler's internal representation -
never generated by an LLM - and must pass the gates. The perturbation engine
applies the operations matrix to produce schema-edit pairs whose diffs are
mechanically checkable; migration tasks derive SQL and the destructive-risk
label from the same op list.

## 6. Benchmark isolation

PrismaBench shares the verifier stack but is a separate artifact: the builder
discards compositions that fail the static validator, withholds references in
the public split, publishes provenance hashes (consumed by the stage-07
firewall), embeds canaries in every task, and withholds 2 of 12 domains plus
a private 50% rotating split.

## 7. Serving

FastAPI (`inference/server/app.py`) exposes `/v1/generate` (with repair),
`/v1/generate/stream` (SSE token stream + final verdict), `/v1/validate`
(static or full gates), `/health`. Gradio UI (`inference/gradio_app.py`) and
the HF Space app wrap the same pipeline. The inference image ships Node so
server-side repair targets the real gates.

## 8. Failure-mode containment

- Every subprocess has a timeout and captured output; sandbox crashes mark
  records `unverified` instead of killing sweeps.
- The verifier short-circuits at the first failing gate (cost discipline).
- CI: lint + unit/dataset/benchmark tests on 3.10-3.12 + pipeline smoke +
  canary firewall check + an optional node-gates job.
- All build outputs are regenerable from pinned seeds; nothing in the
  training path depends on non-replicable services.
